# Git tooling safety audit

This is a focused comparison of the ultrack reference scripts with the existing
Vibecodium equivalents. It records only safety gaps that remain after adding
`scripts/new-lane`.

| Area             | Vibecodium status                                                                                                                                                                                                                                                         | Remaining safety gap                                                                                                                                                                                                                                                 |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Lane creation    | `scripts/new-lane` validates the type and issue number, sanitizes the slug, resolves `main`, refuses an existing branch/path and canonical nested target, creates a sibling worktree, hardlinks `node_modules`, then delegates binding and labeling to `branch-init.mjs`. | None for lane creation. `VIBECODIUM_SKIP_GH=1` is the local/offline equivalent of ultrack's label opt-out.                                                                                                                                                           |
| Nested worktrees | `scripts/checks/worktree-nesting.mjs` already resolves both repository and worktree paths with `realpathSync`; `new-lane` uses the same boundary rule.                                                                                                                    | None. This is stronger than the reference shell check for symlinked paths.                                                                                                                                                                                           |
| Hooks            | `scripts/install-hooks` activates the tracked `.githooks` directory, and the hooks run the repository checks.                                                                                                                                                             | Unlike `install-git-hooks.sh`, it does not copy hooks into the shared `git-common-dir/hooks`. A checkout missing its tracked `.githooks` can therefore run without these hooks until setup is repaired.                                                              |
| Issue labeling   | `scripts/branch-init.mjs` writes `.vibecodium/branch.json` and performs the existing `gh issue edit ... --add-label in-progress`, warning when `gh` is unavailable.                                                                                                       | The reference `issue-label.sh` also audits/reconciles stale labels; Vibecodium has no equivalent reconciliation command. This lane does not duplicate it.                                                                                                            |
| Worktree cleanup | `scripts/worktree-sweep.mjs` is dry-run by default and only prunes clean, merged, aged, non-primary, non-`main` worktrees.                                                                                                                                                | It calls `realpathSync` on every listed path without a per-entry recovery path, so a stale/broken worktree record can abort the sweep instead of being reported and skipped. It also accepts unknown flags; callers should use only its documented `--prune` switch. |

The audit does not add alternate hook, labeling, nesting, or cleanup tools;
those are separate follow-ups if the residual gaps need to be closed.
